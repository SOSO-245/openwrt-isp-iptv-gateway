# IPTV 自动发现与保守更新

本模块是可选的源码扩展，尚未包含在仓库既有 1.1.5 发布包中。它使用已开通的本地 IPTV 业务，不提供公共直播源，不保证发现运营商全部节目。

最新修复已在获准的试运行环境部署：同名换源的失败证据窗口对齐为09:00–22:00；取流在连接成功后按剩余4秒/10秒总预算等待响应，避免1秒连接超时误用于节目起流。一次四地址对照确认了等待满预算及晚间证据采集，但仍存在收到数据而短样本未识别媒体的情况；不能据此证明全部异常根因或长期维护闭环已完成验收。源码扩展尚未发布到既有安装包。

**后续解析修复已获准部署：** 已用合成高复用码率 MPEG-TS 复现短样本只有编解码器名称、却缺少有效视频尺寸或音频采样率/声道数时仍被计为成功的问题。新解析逻辑将这种结果标为待复核，保留合法纯音频节目，并记录音频/视频识别范围及固定解析原因；不扩大样本上限、不自动追加取流、不回填旧证据。192项Python测试通过、无跳过，含真实FFmpeg/FFprobe合成样本；前端未改，本轮未重跑此前25项Node测试。仅NAS发现容器更新一次，健康/源码哈希/持久状态及旁路由配置和节目单一致性已核验，没有追加现场取流。真实异常频道原因仍需独立现场证据。

## 分工与入口

- 旁路由连接 IPTV 专网：`router.py` 每日短时采样，只向 NAS 发送组播地址、包数和节目单基线；不保存或上传整份抓包。
- NAS 只连接家庭 LAN：`server.py` 通过旁路由已有 udpxy 逐个取流，用 FFprobe 识别音视频与可用的节目名称；NAS 不需要 IPTV 网线或 host 网络。
- `playlist_update.py` 仅在旁路由本地合并正式节目单，NAS API 不直接写正式文件。
- 六区控制台位于 `openwrt/data/www/iptv/`，其中 `discovery.js/css` 提供发现与任务页面，共用原管理页面登录。工具图标为 Lucide，许可证随源码保留；`glass.css` 和本地位图提供玻璃主题及应用图标。
- `test_discovery.py` 覆盖边界、调度、暂停续跑、名称和排序、备份及失败回退；`test_release.py` 补充本机 HTTP、真实 FFmpeg/FFprobe 媒体解析及临时目录内的节目单写入验证。

管理页登录使用独立的 IPTV 账号，不自动沿用 LuCI/SSH 账号。HTTP 与 HTTPS 使用同一份服务端认证文件，但浏览器登录状态按来源隔离，切换到 HTTPS 后需要重新登录。登录凭据通过 POST 正文发送，页面仅将明确的 `FAIL` 视为账号密码不正确；HTTP 异常、网络失败、超时和异常响应分别提示，不回显服务端原始内容。此项不修改现有密码，也不是整套旧认证系统的安全改造：旧操作接口与浏览器会话凭据方式仍待独立审阅。包含密钥的设置继续要求 HTTPS。

## 计划与限制

时间按北京时间计算。新安装必须明确配置是否启用，各项互相独立：

| 操作 | 行为 |
| --- | --- |
| 日常采样 | 最多 10 秒、600 个包头，不主动加入全部组播组；支持仅周一至周五，时间可设置 |
| 每日附加扫描 | 可选，默认关闭；每轮最多 8 个地址 |
| 每周全量检查 | 按当前正式节目单、历史已发现地址和已配置范围新建一轮，从第一项逐个检查；不只续扫旧轮剩余频道。日期/时间可设置，与日常采样同一时刻时只执行全量检查 |
| 手动操作 | 采样、最多 8 个地址扫描、最多 4 个地址验证/无响应复查、单地址深度识别、频道表匹配、名称确认/撤回、重新全量、继续全量/批量、暂停、差异与历史、JSON/M3U 导出 |
| 批量操作 | 选择本页或筛选结果，最多 32 个已记录地址自动识别与二次验证，或仅验证；单独批量深度识别最多 8 项 |
| 全量后自动处理 | 可选，默认关闭；一轮全量真正完成后，对最多 32 个有音视频且需定名/复核的新候选执行一次批量流程，不反复重试 |

十秒被动采样不是完整频道表或 EPG 采集。只有旁路由接 IPTV 网线、无人播放时，交换机可能不转发未订阅组播，采样为零不代表无频道。

主动扫描范围只允许现有节目单覆盖的 `/24` 子网，合计最多 256 个地址、两个现有端口；不是扫描整个 `239.0.0.0/8`。全量目标去重后最多 4096 项，单次执行预算一小时，超时保留进度。每个地址最多读取约 4 秒、1 MiB，媒体分析另限 3 秒；逐个处理且保留连接回收间隔。不能据此承诺全部频道识别成功。

TCP连接仍限1秒；连接、发送请求、等待响应头与读取数据共用上述取流总预算，深度识别共用10秒总预算，不在每次读取时重置。连接/发送超时、连接拒绝或重置等传输错误标为“待复核”，不作为频道无响应证据；成功连接后等待响应头或数据超时且未取得任何数据，才标为本次无响应。每个地址保留最新 `last_probe` 的阶段、固定原因码、耗时、字节数及HTTP状态，不记录原始错误字符串、媒体或密钥。旧记录没有这些信息时不补造原因。

解析结果另保存在 `last_probe.analysis`：`audio_only`、`video_only`、`audio_video` 表示本次取得有效参数的流范围，不等同完整播放或画面正确验收。已声明的音视频流只要有一条缺少关键参数，即为 `stream_parameters_incomplete`、待复核；FFprobe失败、超时、不可用或返回异常也不作为频道静默。该结果中断成功计数，不累计换源/归档失败证据，保留上次已知媒体信息并标记本次待复核。未识别到音视频为 `no_av_streams`，也不是永久下线证明。高码率或长关键帧间隔下，8 MiB深度样本仍可能不完整；不自动提高上限、重试或改写未知名称。自动后处理仍只选已确认媒体，解析不确定的候选不会因收到字节被强行入库。

检测到已有 udpxy 播放连接、入口失效或地址/主进程变化时暂停，不据此计为频道失效。检查结束前会等待自身短连接回收；真实播放仍可能在检查间隙开始，不能保证绝对零影响。主进程判定排除继承相同参数的取流子进程。

全量检查保存目标及进度，服务重启后标为暂停，可从页面继续。手动继续保留本轮已完成项目，不自动复查它们；每周计划新建轮次并保留上一轮摘要，历史观察和验证证据不清空。每日/每周计划当天只尝试一次；设备在计划时刻关机或网络不可用时不会自动补跑，页面可手动执行。入口心跳约 15 秒，45 秒未更新停止检测，不是瞬时 DHCP 事件回调。

短采样提交、手动检查/名称确认/频道表匹配、每周检查提交与自动合并共用旁路由的节目单操作锁。采样完成后重新读取最新正式节目单，在同一锁内发送给 NAS；手动检查先同步当前节目单，得到确认后才启动。忙碌时立即返回稍后重试，不长时间排队、不提交旧快照；状态查看和暂停不受该锁阻挡。锁不覆盖十秒抓取本身，也不会锁住正常播放。网络失败会释放锁，后续可手动重试；该保护协调本模块内的正常请求，不是跨 NAS 的分布式事务，不能保证超时后的远端执行状态或不守锁外部程序的写入顺序。

管理页显示下一次短采样和全量检查的北京时间，排除周末及当日已尝试的计划；显示计划不等于保证执行成功。“无响应 / 待复核”筛选按最新检查结果显示，不用旧的成功记录掩盖本次失败。“复查无响应”每次选择最多四个最久未检查的异常地址，仍受播放占用与单任务保护；不会自动扩大扫描范围，建议在频道正常播出时手动执行。

每种计划另保留最近一次执行结果，先记录当日尝试再联系 NAS。NAS 不可达、采样失败或任务提交未确认会明确记录，不反复自动提交。全量接口返回成功仅显示“已提交”，不当作全量完成；完成程度仍以 NAS 检查进度为准。中途退出或最终记录写入失败会保留“未确认”，需要刷新核对。旧日期标记保持兼容，没有旧执行详情时不编造记录；设备关机时未执行的计划也不补造成功或失败。

NAS 暂时离线时，认证后的管理页仍能读取旁路由本地计划和上次尝试；旧扫描结果明确标为未更新，扫描、确认名称和保存按钮暂停，恢复后刷新即可继续。首次打开时若 NAS 不可达，数量保持未知，不显示虚构的零频道。此功能不关闭自动更新配置，不重启或自动修复 NAS。

## 批量工作流

源发现表格支持逐行勾选、选择本页、选择筛选结果（最多32项）和清空。选择“自动识别与二次验证”后，一次提交依次验证信号、按需深度识别、间隔至少60秒再次验证；等待时不占用取流连接。新候选即使短采样读到了节目名称，仍做深度识别，随后使用相同深度再次验证，避免短样本漏读名称或尺寸导致证据反复重置。正式节目和仍有效的人工命名不重复深度定名；无信号和多节目流不被强制定名，跳过的步骤不伪造成功证据。

任务保存目标和步骤进度，可暂停或在重启后继续；遇到播放占用、入口变化、存储错误仍停止。新批量任务替换未完成任务前须确认，但不清空已有观察记录。自动后处理不能覆盖未完成的人工批量任务，提交失败会显示原因；不会无限排队或持续扫描。全量的“重新开始”和“继续上次”是两个明确操作，旧后台能力不足时禁止发送，避免静默变成另一种行为。

自动任务页的“全量后自动识别与复核”写入 NAS 设置 `auto_process`，默认关闭，与旁路由的 `auto_update` 独立。前者补足名称/验证证据，后者按下述保护规则更新节目单；都开启才构成全量后的自动处理链。对当前已经完成的旧全量，不因打开开关立即补跑。名称仍不可靠时必须核对，AI 辅助诊断不会猜测频道名或绕过入库条件。

默认结果视图将从未识别到媒体、且不在正式节目单中的无响应候选单独归类，可切换“无响应候选”或“全部结果”查看；曾成功的源及正式频道异常仍保留。此处是筛选，不是删除，也没有“三次失败自动删正式频道”规则。每行显示等待名称、有效复核进度或节目单状态，批量栏显示自动识别与自动入库是否启用。

结果上方按“待识别 / 待复核 / 待更新核验 / 正式节目异常”显示数量并可直接筛选，再使用原有批量操作。最后一类新源表示等待后台更新校验，不代表前端已经批准入库；无可靠名称的源不自动推测节目身份。

## 名称待识别

- 地址已在正式节目单：使用原有名称兜底；流中读到名称时也保留节目单本身，扫描不会擅自重命名旧频道。
- 新地址有明确的单节目名称：记录为候选，经重复验证后才允许自动加入。
- 新地址只有音视频、没有节目名称：保留“名称待识别”。现有短采样可能错过名称表，也可能是节目流不提供名称。
- 每行“深度识别”只对一个已记录地址取流，最多约 10 秒或 8 MiB，FFprobe 分析另限 5 秒；保留播放占用、入口变化、暂停和单任务保护。高码率会先触及字节上限，并非保证采满十秒，亦不保证流中存在名称。
- “匹配频道表”读取旁路由已有 `/www/vsp.m3u`，只传频道名、组播地址/协议和文件时间到 NAS，不读取机顶盒凭据或访问运营商门户。仅准确地址与协议匹配；唯一名称显示“频道表候选”，多个名称保留歧义。缓存可能过时，不自动据此入库。
- 新地址已验证音视频且非多节目流时，可在每行确认名称，须勾选已核对画面/可靠频道表；支持撤回和历史记录。确认绑定当前流身份，后续身份变化永久标为失效，须重新核对。不能在此改已存在的正式频道名。
- 分辨率、相邻地址、节目内容相似都不构成可靠名称证据；不自动据此猜频道。

## 自动更新规则

1. 仅接受最近七天内、至少两次成功且间隔至少 60 秒的音视频源；两次记录须绑定同一地址/协议/节目与音视频信息。失败、结果不确定或流身份变化后重新累计，旧版无时间戳的次数不能直接充当证据；新源显示有效复核进度。须有明确单节目名称或仍有效的人工确认。无节目表但已人工确认的单音视频源可入库；泛化名称、多节目、危险字符和未确认的缓存候选不自动加入。人工确认不是运营商认证，操作者仍须核对画面。
2. 新频道按原项目分类插入：4K/UHD、CCTV 数字序（含 5+）、主要省级卫视、其他卫视、既有 VSP/地方节目、原有其他节目、国外频道。原条目的相对顺序保留。
3. 同名换址必须名称唯一匹配，且旧源在最近七天内至少三次有效时段内无响应：北京时间 09:00（含）至 22:00（不含），每次间隔至少一小时，整体跨度至少 24 小时，最新检查仍须为无响应。时段外记录和旧版累计次数仅供查看，不满足换址条件；无媒体/分析不确定不等同无响应。原源仍可用时只保留待确认，不自动覆盖。有效时段内也可能临时停播，流中名称并非运营商认证身份，仍可能存在误标风险。原字段名 `daytime_failure_checks` 保留兼容，不回填之前未记录的晚间证据。
4. 默认不移除频道；可单独开启下述长期失效归档，不永久删除记录。一次变更多于 16 项时停止自动合并，等待核对。
5. 基础版与台标版必须名称/地址成对一致；写入前保存三份旧文件及清单，保留既有元数据、台标和播放地址前缀。无对应台标时留空，不编造台标链接。
6. 备份位于 `/etc/iptv-discovery-backups/update-*/`；保留最多 50 次，达到后暂停更新，不自动删除用户备份。

### 长期失效自动归档

安装默认关闭，由独立 `auto_archive` 开关控制，首次启用必须单独确认；同时依赖 `auto_update`。不是三次连续点击复查就删节目，不永久删除频道资料。

- 只从新版本完成的合格全量检查积累归档证据：本轮24小时内完成并覆盖全部正式节目，入口身份未变化，结果均明确，至少两个正常节目，正式节目无响应比例不超过20%；失败节目同一 `/24` 和端口还有正常对照。旧的普通失败次数不追认为归档依据。
- 同一节目至少在3个不同日期、北京时间09:00（含）至22:00（不含）检查无响应，首尾跨度至少7天；19:00检查属于有效时段。证据保留30天，最近一轮及全量覆盖必须在24小时内。成功、无媒体或分析不确定会中断该失效证据链。未完成全量、网络/存储异常和任务忙碌不执行归档。与同名换址使用相同有效时段，但归档的独立证据、完整全量及更长跨度条件不变。
- 每轮最多5条且不超过正式节目5%（小节目单最低1条）。达到大面积异常或超限保护时整批归档暂停，不分批绕过上限。
- 归档从三份正式节目单移除条目，但在成功事务备份清单保留原名称、地址、元数据、台标及前后排序参照。已有三文件备份、同步确认和异常回退保护继续适用。
- 以后扫描恢复媒体、可靠名称与归档身份一致，并满足两次间隔验证后自动恢复；多个节目恢复次序不同也保留原相对排序。若名称变化不猜测恢复。归档地址仍留发现历史，后续全量会复查；历史上限等原因导致地址不在扫描范围时需重新纳入检查。
- 不改变每周扫描时间。若仅每周检查一次，取得3个不同日期的合格记录通常至少跨两周，不承诺第7天必定归档。短采样、被动零观察与有效时段外的检查不会加速这个过程。

源发现新增“最近节目单变更”，只读取已成功提交的备份清单，展示新增、换源、归档、恢复及时间；后来一轮无变化不会把上次成功记录抹掉。自动后处理区分提交、完成、暂停、错误，并保留人工/自动触发来源；手动批量后入库不能表述为整轮自动完成。

程序采用独立锁、旧管理任务检测、逐份写入前内容比对、单文件原子替换和异常回退。失败时仅回退内容仍与本次写入完全一致的文件；其他任务的改动或删除会保留。一份回退失败不阻止其他可安全恢复的文件，结果与冲突文件名记录在备份清单中。

新清单在正式写入前保存三份文件的更新前/预期更新后哈希；备份、清单及文件替换均刷新文件与父目录。中断后留下 `prepared`、`rolling_back`、`needs_review` 或损坏清单时，后续自动合并会暂停并显示备份编号，不自动猜测应保留哪一版。已完成旧版清单兼容保留；尚未生成清单的备份目录表示未开始正式写入，不触发恢复。三份节目单仍不是跨文件原子事务，文件系统/硬件断电保证以及不遵守同一锁的外部写入仍有窗口，不能承诺绝不出现混合版本；避免并行手工改节目单。

本地合并成功与 NAS 收到新基线分开确认。如果同步响应丢失，页面显示“已更新 · NAS待同步”，保留成功时间、变更与备份位置。自动更新启用且 NAS 空闲、存储正常时，至少间隔五分钟仅重新同步当前正式节目单，不再执行本地合并；收到确认后才清除待同步状态。期间暂停新的自动合并，停用自动更新也停止补同步。记录位于 `/tmp/iptv-discovery/update.json`，可跨本模块服务重载，但不承诺跨整机断电保留；该保护不能替代三文件断电恢复验收。

## 安装与配置

部署前备份现场 HTML 和节目单。现场 HTML 可能带有私人配置，不应直接被公开源码版本覆盖。

### NAS

在专用目录保留本目录的 `Dockerfile`、`compose.yaml`、`server.py`、`common.py`。创建私密 `.env`，明确设置 `ROUTER_IP`、`NAS_IP`、`DISCOVERY_SUBNET` 和该子网对应的 `DOCKER_GATEWAY`；先确认不与现有 LAN、IoT 或容器网络冲突。公开版不预填作者现场地址；缺少必填项时 Compose 会拒绝启动。

创建随机长令牌 `api-token`，文件仅容器 UID 1000 可读；`data/` 归 UID/GID 1000。同一令牌仅写入旁路由私密配置，不放进 Git、截图、日志或公开示例。随后在该目录执行 `docker compose up -d --build`。

镜像构建会将两份程序源码设为只读可访问的 `644`，避免复制时继承主机 `600` 权限而导致非 root 容器无法启动；不改变令牌或数据目录权限。更新前可用 `docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --entrypoint python3 local/iptv-discovery:1.0 -c 'import server, common'` 检查镜像能否以其默认非 root 用户读取程序，此检查不挂载生产数据、不访问网络。

容器非 root、只读根文件系统、移除 capabilities、256 MiB 内存限制、CPU 权重降低、有限临时空间和日志。DSM 的 CPU 权重不是硬限速。仅将 API 绑定 NAS LAN 地址的 18086 端口，不映射公网。`/health` 返回简短健康信息，其他 API 要求 Bearer 令牌及允许的 LAN 来源。部分 NAS 用户态端口转发会把来源改成 Docker 网关，故不能只依靠来源 IP 授权。

磁盘满、只读等状态保存失败时，未保存的名称确认和检测结果会撤回到上次保存状态；任务标为错误并释放锁，避免一直卡在“运行中”。页面显示存储警告，健康接口返回503，旁路由停止自动合并。修复存储后，下一次正常保存恢复健康状态，手动继续从已保存进度执行；不必通过重启清除任务锁，也不会清除历史记录。

### 旁路由

需要现有正常工作的 `br-iptv`、udpxy 12123、tcpdump 和 Python 3 标准库。`/etc/iptv-input-iface` 必须指向真实的 IPTV 成员口，程序不会自动退回 LAN 抓包。

- 将 `router.py`、`common.py`、`playlist_update.py`、`ai_diagnostics.py` 放入 `/usr/lib/iptv-discovery/`。
- 将 `iptv-discovery.cgi` 安装为可执行 `/www/cgi-bin/iptv-discovery`，`iptv-discovery.init` 安装为可执行 `/etc/init.d/iptv-discovery`。
- 私密 `/etc/iptv-discovery.json` 权限 600，包含：`nas_host`、`nas_port`（18086）、`token`、`enabled`、`daily_time`（HH:MM）、`weekdays_only`、`weekly_enabled`、`weekly_day`（周一0至周日6）、`weekly_time`、`auto_update`、`auto_archive`（缺省false）。首次可将启用项均设 false，再从页面启用。仅工作日指周一至周五，不处理法定节假日/调休。
- 新版控制台需要成套同步 `index.html`、`wiki.html`、`actions.js`、`channels.js`、`playlist-model.js`、`console.css/js`、`discovery.css/js`、`discovery-model.js`、`ai-diagnostics.js`、`icons.js`、`control-icons.js` 及 `lucide-LICENSE`。先备份旧页面并核对私人配置，保留既有认证、台标库和其他数据；不要只在旧 HTML 增加五个引用，新旧页面结构并不兼容。批量功能还需要更新 NAS 的 `server.py` 并在空闲时重建本模块容器；保留数据、环境、网络和限制。此步骤属于单独部署，不由 GitHub 源码同步自动执行。
- 玻璃主题另需 `glass.css` 与 `assets/` 中的 `glass-waves.webp`、`iptv-icon.png`、`iptv-mark.png`、`favicon.png`、`apple-touch-icon.png`。只复制这些指定素材，不覆盖现场台标或其他资源；先更新依赖，再更新HTML。仅静态界面更新不需重启服务，回退时恢复旧HTML并按部署清单恢复旧资源，不改后台或节目单。
- 单独启用/启动 `/etc/init.d/iptv-discovery`；无需重启路由器、udpxy 或代理。

本模块只观察 IPTV 地址是否与取流进程一致，DHCP 源地址联动仍由原有正式 hotplug 脚本负责。不要在 `/etc/hotplug.d/iface/` 保存脚本备份，部分 OpenWrt 分发会执行该目录全部文件。

### 可选 AI 辅助诊断

源码新增 DeepSeek 适配，入口为源发现的“AI 分析”和系统维护的“AI 辅助诊断”；不替代原有本地诊断，不随定时任务调用。前端依赖 `ai-diagnostics.js`，须与新增页面入口和后台模块成套部署。已在一台设备部署并验证未配置状态、真实摘要预览和取消；真实密钥与云端调用仍未验收，本地成功回复仅为模拟。

- 固定官方接口 `https://api.deepseek.com/chat/completions`，默认保留 `deepseek-v4-flash`；也支持官方推荐别名 `deepseek-flash`。接口参数依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/api/create-chat-completion)，模型可用性及计费仍须以账号实际响应为准。
- 在“系统维护 → AI 辅助诊断 → API 设置”编辑官方 Base URL、模型与 API Key；未配置摘要也有直达入口。支持官方根地址或 `/v1` 地址，统一使用官方 HTTPS 目的地，不接受其他主机。密钥由用户在密码框填写，保存后不回显，留空保留旧值；首次配置不能留空。不在浏览器存储中保存密钥，关闭/提交后清空输入框。
- HTTP 管理页禁止输入、保存和测试 AI 密钥，没有风险勾选放行。必须使用设备 HTTPS 页面，或通过交互式 SSH 执行 `python3 /usr/lib/iptv-discovery/ai_diagnostics.py --configure` 隐藏输入。TLS状态只取可信CGI环境，不采信浏览器或转发头声明；自签名证书由用户核对，不自动跳过警告。设备到 DeepSeek 始终校验证书并使用 HTTPS。不要把密钥放在聊天、命令参数、公开配置或日志。
- “连接测试”独立于保存，使用当前表单或留空时的已存密钥请求官方 [`GET /models`](https://api-docs.deepseek.com/api/list-models/)，检查认证与所选模型是否列出；不发起诊断生成，不发送家庭数据，不保存草稿。支持认证/权限、模型未列出、限频、网络、TLS与超时反馈；总时限12秒、15秒请求间隔、无自动重试。列表通过不等于诊断生成或计费额度已验收，模型不在列表中时不自动替换。
- 设置经现有账号认证后，原子保存到服务账号独占的 `/etc/iptv-ai.json`（600）；拒绝权限异常文件和符号链接。这是访问权限保护，并非加密存储，设备管理员仍可读取。保存不发起云端请求，不重启服务，且会使旧摘要票据失效。保存、测试和诊断共用互斥锁。配置密钥不等于认证/模型可用性已验证，真实诊断仍须预览摘要并手动确认。
- 用户先选择问题并预览白名单摘要：只含状态、布尔值及数量，不发送地址、频道名称、完整日志、账号、订阅或抓包。未知保持未知，不显示虚构的正常或零值。摘要可能包含历史检查结果，不是持续监控或新的主动测试。
- 每次明确确认后，只发送刚才预览的摘要；五分钟过期，绑定登录账号和所选模型。单请求互斥、一分钟冷却，先消耗确认票据再发送；超时或响应丢失不自动重复付费请求。请求总时限30秒、回复最多1600 tokens，无工具执行能力。
- 回复按纯文本显示，不执行命令、不打开模型链接，不自动重启、扫描、改网或删频道。建议必须人工核对。临时摘要放在私有 `/tmp/iptv-ai/`，不保存模型回复，不收集原始网络数据。

`python3 discovery/console_fixture.py --ai-configured` 可体验本机模拟成功回复，增加 `--ai-fail` 可模拟失败；增加 `--ai-secure-fixture` 仅在本机样例中模拟HTTPS状态以测试表单，仍不是TLS验收，不输入真实密钥。所有模拟均不联系云端。普通启动不模拟已配置密钥。撤回功能时成套恢复页面和 CGI 源码，不动原采样计划或节目单；私密密钥文件不进入备份公开包。

## 回退与验证

停用自动更新和新调度服务即可停止采样/扫描触发；NAS 有任务时先暂停，再停止本模块容器。回退新版控制台时成套恢复更新前备份的 HTML/CSS/JS，不仅移除资源引用；保留认证、台标库、节目单与其他数据。恢复节目单时三份文件应来自同一更新备份，保持服务端已有读权限；不要重置网络或删除容器数据。

遇到未完成更新提示时，先停止自动更新、保存当前三份文件及相关 `update-*` 备份，然后对照清单 `before`/`after` 哈希核对。存在外部改动时应人工保留/合并，不整批覆盖。恢复成对一致版本并核对 NAS 基线后，再把该次完整备份移入单独归档目录以解除阻断；不要只删除清单、伪造完成状态或清空备份。这里不提供自动强制恢复按钮。

本地验证：`python3 -m unittest discover -s discovery -v`、`node --check openwrt/data/www/iptv/discovery.js`、`git diff --check`。`python3 discovery/ui_fixture.py` 启动随机本机端口的 UI 样例，可加 `--storage-error` 查看模拟存储警告、`--offline` 查看离线初始页、`--outage-cycle` 验证正常/断线/恢复过程，或 `--sync-cycle` 查看节目单待同步与确认后的变化；临时数据随进程退出清理。该入口不连接路由器/NAS，不支持采样或生产写入。

自动测试覆盖名称候选不自动入库、人工确认/撤回/失效/持久化、深度识别范围与读取上限、工作日及周五去重、日期化媒体证据、流身份变化与失败重置、夜间/旧计数不能换源、最旧四项复查及下一次计划时间。新增批量测试覆盖已知目标范围/上限、无信号跳过、按间隔实际复核、未知名称保护、播放暂停/恢复、等待中暂停、不覆盖未完人工任务和后处理失败可见；页面模型覆盖分类与能力门控。界面样例使用虚构频道与文档示例地址，不连接生产设备。

当前源码本地测试共 168 项 Python 和 25 项 Node 测试通过、无跳过，包括六区控制台样例与频道编辑保护、随机令牌鉴权、真实 HTTP 调用、合成 MPEG-TS 的 FFprobe 解析、状态重新载入、节目单备份与幂等写入，以及无法识别 LAN 网关时停止修复而不写配置。`test_recovery.py` 另覆盖每周重新全量/手动续跑、写入失败撤回、任务锁释放、线程启动失败及存储恢复；接口测试核验503与恢复后200。`test_schedule_status.py` 覆盖计划失败留痕、零流量采样、提交超时不重试、日期标记保存失败及离线状态读取。`test_update_sync.py` 覆盖更新后同步失败、五分钟节流、仅补同步、存储异常/扫描占用保护、停用后不重试、最终确认保存失败与成功记录保留。`test_playlist_transaction.py` 覆盖14项故障注入：外部改动/删除保护、每次写入及回退途中中断、写入后目录刷新失败、单文件回退失败、清单无法保存及旧版记录兼容；均使用临时目录，不是实际拔电验收。`test_baseline_coordination.py` 另有11项覆盖旧快照复现、捕获与提交的锁范围、合并互斥、空节目单拒绝、失败释放锁、检查/名称确认/频道表同步及忙碌时仍可暂停和查看状态。新增 AI 诊断测试使用本地模拟，覆盖摘要隐私、密钥权限/HTTPS门控/私有保存、模型列表连接测试、确认票据、调用互斥、冷却及失败保护，不代表真实云端接口验收。媒体集成测试需要本机安装 `ffmpeg` 和 `ffprobe`；不应把依赖缺失造成的跳过计作通过。

长期归档及09:00–22:00证据窗口已在NAS和旁路由试部署，运行文件、HTTP资源、持久状态与既有计划核验通过。`test_archive.py`覆盖跨日期、时段、大面积异常、归档和恢复排序；部署后另用两端纯内存样例验证09:00/19:00有效、22:00无效，没有触发扫描或写正式节目单。真实长期归档/恢复仍需独立现场验收。
