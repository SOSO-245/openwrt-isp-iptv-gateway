# IPTV 自动发现与保守更新

本模块是可选的源码扩展，尚未包含在仓库既有 1.1.5 发布包中。它使用已开通的本地 IPTV 业务，不提供公共直播源，不保证发现运营商全部节目。

## 分工与入口

- 旁路由连接 IPTV 专网：`router.py` 每日短时采样，只向 NAS 发送组播地址、包数和节目单基线；不保存或上传整份抓包。
- NAS 只连接家庭 LAN：`server.py` 通过旁路由已有 udpxy 逐个取流，用 FFprobe 识别音视频与可用的节目名称；NAS 不需要 IPTV 网线或 host 网络。
- `playlist_update.py` 仅在旁路由本地合并正式节目单，NAS API 不直接写正式文件。
- 六区控制台位于 `openwrt/data/www/iptv/`，其中 `discovery.js/css` 提供发现与任务页面，共用原管理页面登录。图标为 Lucide，许可证随源码保留。
- `test_discovery.py` 覆盖边界、调度、暂停续跑、名称和排序、备份及失败回退；`test_release.py` 补充本机 HTTP、真实 FFmpeg/FFprobe 媒体解析及临时目录内的节目单写入验证。

## 计划与限制

时间按北京时间计算。新安装必须明确配置是否启用，各项互相独立：

| 操作 | 行为 |
| --- | --- |
| 日常采样 | 最多 10 秒、600 个包头，不主动加入全部组播组；支持仅周一至周五，时间可设置 |
| 每日附加扫描 | 可选，默认关闭；每轮最多 8 个地址 |
| 每周全量检查 | 按当前正式节目单、历史已发现地址和已配置范围新建一轮，从第一项逐个检查；不只续扫旧轮剩余频道。日期/时间可设置，与日常采样同一时刻时只执行全量检查 |
| 手动操作 | 采样、最多 8 个地址扫描、最多 4 个地址验证/无响应复查、单地址深度识别、频道表匹配、名称确认/撤回、全量检查、暂停、差异与历史、JSON/M3U 导出 |

十秒被动采样不是完整频道表或 EPG 采集。只有旁路由接 IPTV 网线、无人播放时，交换机可能不转发未订阅组播，采样为零不代表无频道。

主动扫描范围只允许现有节目单覆盖的 `/24` 子网，合计最多 256 个地址、两个现有端口；不是扫描整个 `239.0.0.0/8`。全量目标去重后最多 4096 项，单次执行预算一小时，超时保留进度。每个地址最多读取约 4 秒、1 MiB，媒体分析另限 3 秒；逐个处理且保留连接回收间隔。不能据此承诺全部频道识别成功。

检测到已有 udpxy 播放连接、入口失效或地址/主进程变化时暂停，不据此计为频道失效。检查结束前会等待自身短连接回收；真实播放仍可能在检查间隙开始，不能保证绝对零影响。主进程判定排除继承相同参数的取流子进程。

全量检查保存目标及进度，服务重启后标为暂停，可从页面继续。手动继续保留本轮已完成项目，不自动复查它们；每周计划新建轮次并保留上一轮摘要，历史观察和验证证据不清空。每日/每周计划当天只尝试一次；设备在计划时刻关机或网络不可用时不会自动补跑，页面可手动执行。入口心跳约 15 秒，45 秒未更新停止检测，不是瞬时 DHCP 事件回调。

短采样提交、手动检查/名称确认/频道表匹配、每周检查提交与自动合并共用旁路由的节目单操作锁。采样完成后重新读取最新正式节目单，在同一锁内发送给 NAS；手动检查先同步当前节目单，得到确认后才启动。忙碌时立即返回稍后重试，不长时间排队、不提交旧快照；状态查看和暂停不受该锁阻挡。锁不覆盖十秒抓取本身，也不会锁住正常播放。网络失败会释放锁，后续可手动重试；该保护协调本模块内的正常请求，不是跨 NAS 的分布式事务，不能保证超时后的远端执行状态或不守锁外部程序的写入顺序。

管理页显示下一次短采样和全量检查的北京时间，排除周末及当日已尝试的计划；显示计划不等于保证执行成功。“无响应 / 待复核”筛选按最新检查结果显示，不用旧的成功记录掩盖本次失败。“复查无响应”每次选择最多四个最久未检查的异常地址，仍受播放占用与单任务保护；不会自动扩大扫描范围，建议在频道正常播出时手动执行。

每种计划另保留最近一次执行结果，先记录当日尝试再联系 NAS。NAS 不可达、采样失败或任务提交未确认会明确记录，不反复自动提交。全量接口返回成功仅显示“已提交”，不当作全量完成；完成程度仍以 NAS 检查进度为准。中途退出或最终记录写入失败会保留“未确认”，需要刷新核对。旧日期标记保持兼容，没有旧执行详情时不编造记录；设备关机时未执行的计划也不补造成功或失败。

NAS 暂时离线时，认证后的管理页仍能读取旁路由本地计划和上次尝试；旧扫描结果明确标为未更新，扫描、确认名称和保存按钮暂停，恢复后刷新即可继续。首次打开时若 NAS 不可达，数量保持未知，不显示虚构的零频道。此功能不关闭自动更新配置，不重启或自动修复 NAS。

## 名称待识别

- 地址已在正式节目单：使用原有名称兜底；流中读到名称时也保留节目单本身，扫描不会擅自重命名旧频道。
- 新地址有明确的单节目名称：记录为候选，经重复验证后才允许自动加入。
- 新地址只有音视频、没有节目名称：保留“名称待识别”。现有短采样可能错过名称表，也可能是节目流不提供名称。
- 每行“深度识别”只对一个已记录地址取流，最多约 10 秒或 8 MiB，FFprobe 分析另限 5 秒；保留播放占用、入口变化、暂停和单任务保护。高码率会先触及字节上限，并非保证采满十秒，亦不保证流中存在名称。
- “匹配频道表”读取旁路由已有 `/www/vsp.m3u`，只传频道名、组播地址/协议和文件时间到 NAS，不读取机顶盒凭据或访问运营商门户。仅准确地址与协议匹配；唯一名称显示“频道表候选”，多个名称保留歧义。缓存可能过时，不自动据此入库。
- 新地址已验证音视频且非多节目流时，可在每行确认名称，须勾选已核对画面/可靠频道表；支持撤回和历史记录。确认绑定当前流身份，后续身份变化永久标为失效，须重新核对。不能在此改已存在的正式频道名。
- 分辨率、相邻地址、节目内容相似都不构成可靠名称证据；不自动据此猜频道。

## 自动更新规则

1. 仅接受最近七天内、至少两次成功且间隔至少 60 秒的音视频源；两次记录须绑定同一地址/协议/节目与音视频信息。失败、结果不确定或流身份变化后重新累计，旧版无时间戳的次数不能直接充当证据；新源显示有效复核进度。须有明确单节目名称或仍有效的人工确认。无节目表但已人工确认的单音视频源可入库；泛化名称、多节目、危险字符和未确认的缓存候选不自动加入。人工确认不是运营商认证，操作者仍须核对画面。
2. 新频道按原项目分类插入：4K/UHD、CCTV 数字序（含 5+）、主要省级卫视、其他卫视、既有 VSP/地方节目、原有其他节目、国外频道。原条目的相对顺序保留。
3. 同名换址必须名称唯一匹配，且旧源在最近七天内至少三次白天无响应：北京时间 09:00（含）至 18:00（不含），每次间隔至少一小时，整体跨度至少 24 小时，最新检查仍须为无响应。夜间记录和旧版累计次数仅供查看，不满足换址条件；无媒体/分析不确定不等同无响应。原源仍可用时只保留待确认，不自动覆盖。白天也可能临时停播，流中名称并非运营商认证身份，仍可能存在误标风险。
4. 不自动删除频道。一次变更多于 16 项时停止自动合并，等待核对。
5. 基础版与台标版必须名称/地址成对一致；写入前保存三份旧文件及清单，保留既有元数据、台标和播放地址前缀。无对应台标时留空，不编造台标链接。
6. 备份位于 `/etc/iptv-discovery-backups/update-*/`；保留最多 50 次，达到后暂停更新，不自动删除用户备份。

程序采用独立锁、旧管理任务检测、逐份写入前内容比对、单文件原子替换和异常回退。失败时仅回退内容仍与本次写入完全一致的文件；其他任务的改动或删除会保留。一份回退失败不阻止其他可安全恢复的文件，结果与冲突文件名记录在备份清单中。

新清单在正式写入前保存三份文件的更新前/预期更新后哈希；备份、清单及文件替换均刷新文件与父目录。中断后留下 `prepared`、`rolling_back`、`needs_review` 或损坏清单时，后续自动合并会暂停并显示备份编号，不自动猜测应保留哪一版。已完成旧版清单兼容保留；尚未生成清单的备份目录表示未开始正式写入，不触发恢复。三份节目单仍不是跨文件原子事务，文件系统/硬件断电保证以及不遵守同一锁的外部写入仍有窗口，不能承诺绝不出现混合版本；避免并行手工改节目单。

本地合并成功与 NAS 收到新基线分开确认。如果同步响应丢失，页面显示“已更新 · NAS待同步”，保留成功时间、变更与备份位置。自动更新启用且 NAS 空闲、存储正常时，至少间隔五分钟仅重新同步当前正式节目单，不再执行本地合并；收到确认后才清除待同步状态。期间暂停新的自动合并，停用自动更新也停止补同步。记录位于 `/tmp/iptv-discovery/update.json`，可跨本模块服务重载，但不承诺跨整机断电保留；该保护不能替代三文件断电恢复验收。

## 安装与配置

部署前备份现场 HTML 和节目单。现场 HTML 可能带有私人配置，不应直接被公开源码版本覆盖。

### NAS

在专用目录保留本目录的 `Dockerfile`、`compose.yaml`、`server.py`、`common.py`。创建私密 `.env`，明确设置 `ROUTER_IP`、`NAS_IP`、`DISCOVERY_SUBNET` 和该子网对应的 `DOCKER_GATEWAY`；先确认不与现有 LAN、IoT 或容器网络冲突。公开版不预填作者现场地址；缺少必填项时 Compose 会拒绝启动。

创建随机长令牌 `api-token`，文件仅容器 UID 1000 可读；`data/` 归 UID/GID 1000。同一令牌仅写入旁路由私密配置，不放进 Git、截图、日志或公开示例。随后在该目录执行 `docker compose up -d --build`。

镜像构建会将两份程序源码设为只读可访问的 `644`，避免复制时继承主机 `600` 权限而导致非 root 容器无法启动；不改变令牌或数据目录权限。更新前可用 `docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --entrypoint python3 local/iptv-discovery:1.0 -c 'import server, common'` 检查镜像能否以其默认非 root 用户读取程序，此检查不挂载生产数据、不访问网络。

容器非 root、只读根文件系统、移除 capabilities、256 MiB 内存限制、CPU 权重降低、有限临时空间和日志。DSM 的 CPU 权重不是硬限速。仅将 API 绑定 NAS LAN 地址的 18086 端口，不映射公网。`/health` 返回简短健康信息，其他 API 要求 Bearer 令牌及允许的 LAN 来源。部分 NAS 用户态端口转发会把来源改成 Docker 网关，故不能只依靠来源 IP 授权。

磁盘满、只读等状态保存失败时，未保存的名称确认和检测结果会撤回到上次保存状态；任务标为错误并释放锁，避免一直卡在“运行中”。页面显示存储警告，健康接口返回503，旁路由停止自动合并。修复存储后，下一次正常保存恢复健康状态，手动继续从已保存进度执行；不必通过重启清除任务锁，也不会清除历史记录。

### 旁路由

需要现有正常工作的 `br-iptv`、udpxy 12123、tcpdump 和 Python 3 标准库。`/etc/iptv-input-iface` 必须指向真实的 IPTV 成员口，程序不会自动退回 LAN 抓包。

- 将 `router.py`、`common.py`、`playlist_update.py` 放入 `/usr/lib/iptv-discovery/`。
- 将 `iptv-discovery.cgi` 安装为可执行 `/www/cgi-bin/iptv-discovery`，`iptv-discovery.init` 安装为可执行 `/etc/init.d/iptv-discovery`。
- 私密 `/etc/iptv-discovery.json` 权限 600，包含：`nas_host`、`nas_port`（18086）、`token`、`enabled`、`daily_time`（HH:MM）、`weekdays_only`、`weekly_enabled`、`weekly_day`（周一0至周日6）、`weekly_time`、`auto_update`。首次可将三个启用项均设 false，再从页面启用。仅工作日指周一至周五，不处理法定节假日/调休。
- 新版控制台需要成套同步 `index.html`、`wiki.html`、`actions.js`、`channels.js`、`playlist-model.js`、`console.css/js`、`discovery.css/js`、`icons.js`、`control-icons.js` 及 `lucide-LICENSE`。先备份旧页面并核对私人配置，保留既有认证、台标库和其他数据；不要只在旧 HTML 增加五个引用，新旧页面结构并不兼容。此步骤属于单独部署，不由 GitHub 源码同步自动执行。
- 单独启用/启动 `/etc/init.d/iptv-discovery`；无需重启路由器、udpxy 或代理。

本模块只观察 IPTV 地址是否与取流进程一致，DHCP 源地址联动仍由原有正式 hotplug 脚本负责。不要在 `/etc/hotplug.d/iface/` 保存脚本备份，部分 OpenWrt 分发会执行该目录全部文件。

## 回退与验证

停用自动更新和新调度服务即可停止采样/扫描触发；NAS 有任务时先暂停，再停止本模块容器。回退新版控制台时成套恢复更新前备份的 HTML/CSS/JS，不仅移除资源引用；保留认证、台标库、节目单与其他数据。恢复节目单时三份文件应来自同一更新备份，保持服务端已有读权限；不要重置网络或删除容器数据。

遇到未完成更新提示时，先停止自动更新、保存当前三份文件及相关 `update-*` 备份，然后对照清单 `before`/`after` 哈希核对。存在外部改动时应人工保留/合并，不整批覆盖。恢复成对一致版本并核对 NAS 基线后，再把该次完整备份移入单独归档目录以解除阻断；不要只删除清单、伪造完成状态或清空备份。这里不提供自动强制恢复按钮。

本地验证：`python3 -m unittest discover -s discovery -v`、`node --check openwrt/data/www/iptv/discovery.js`、`git diff --check`。`python3 discovery/ui_fixture.py` 启动随机本机端口的 UI 样例，可加 `--storage-error` 查看模拟存储警告、`--offline` 查看离线初始页、`--outage-cycle` 验证正常/断线/恢复过程，或 `--sync-cycle` 查看节目单待同步与确认后的变化；临时数据随进程退出清理。该入口不连接路由器/NAS，不支持采样或生产写入。

自动测试覆盖名称候选不自动入库、人工确认/撤回/失效/持久化、深度识别范围与读取上限、工作日及周五去重、日期化媒体证据、流身份变化与失败重置、夜间/旧计数不能换源、最旧四项复查及下一次计划时间。界面样例使用虚构频道与文档示例地址，不连接生产设备。

当前源码本地测试共 104 项 Python 和 8 项 Node 测试通过、无跳过，包括六区控制台样例与频道编辑保护、随机令牌鉴权、真实 HTTP 调用、合成 MPEG-TS 的 FFprobe 解析、状态重新载入、节目单备份与幂等写入，以及无法识别 LAN 网关时停止修复而不写配置。`test_recovery.py` 另覆盖每周重新全量/手动续跑、写入失败撤回、任务锁释放、线程启动失败及存储恢复；接口测试核验503与恢复后200。`test_schedule_status.py` 覆盖计划失败留痕、零流量采样、提交超时不重试、日期标记保存失败及离线状态读取。`test_update_sync.py` 覆盖更新后同步失败、五分钟节流、仅补同步、存储异常/扫描占用保护、停用后不重试、最终确认保存失败与成功记录保留。`test_playlist_transaction.py` 覆盖14项故障注入：外部改动/删除保护、每次写入及回退途中中断、写入后目录刷新失败、单文件回退失败、清单无法保存及旧版记录兼容；均使用临时目录，不是实际拔电验收。`test_baseline_coordination.py` 另有11项覆盖旧快照复现、捕获与提交的锁范围、合并互斥、空节目单拒绝、失败释放锁、检查/名称确认/频道表同步及忙碌时仍可暂停和查看状态。媒体集成测试需要本机安装 `ffmpeg` 和 `ffprobe`；不应把依赖缺失造成的跳过计作通过。

提交前运行 `python3 scripts/check_public_source.py` 检查本次改动中的私密文件、家庭地址和凭据特征，并另行检查完整源码及 Git 历史的凭据泄漏。该脚本只检查变更集合，不覆盖旧二进制包、历史提交或图片内容，不能替代人工审阅。旧发布包不包含本模块，不应在相同版本名下静默替换。
